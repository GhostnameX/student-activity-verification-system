เพิ่มฟีเจอร์: สร้าง PDF "แบบคำร้องขอตรวจสอบกิจกรรม" ตามแบบฟอร์มจริงของคณะวิทยาการจัดการ PSRU
โดยระบบกรอกข้อมูลอัตโนมัติแทนการเขียนมือ แนบไปกับอีเมลตอน staff/admin กด approve
(endpoint POST /api/requests/:id/approve ใน apps/api/src/app.ts)

## อ้างอิงแบบฟอร์มต้นฉบับ
ใช้ไฟล์ต้นฉบับ `2569_แบบคำร้องขอตรวจสอบกิจกรรม.pdf` **เป็น template โดยตรง** — โหลด PDF นี้ด้วย `pdf-lib` (`PDFDocument.load`) แล้ว **เขียนข้อความทับลงไปบนหน้าเดิม** (ไม่ต้องวาดโลโก้/เส้น/หัวกระดาษใหม่เอง เพราะมีอยู่แล้วในไฟล์) — เก็บไฟล์ template นี้ไว้ที่ `apps/api/assets/forms/activity-request-form.pdf`

ตำแหน่งที่ต้อง**เขียนทับ**ลงบน template (วัด coordinate x/y จริงจากไฟล์ต้นฉบับตอน implement เพราะขนาดหน้า/ตำแหน่งจุดไข่ปลาต้องเป๊ะ):

1. มุมขวาบน: "คำร้องที่ ........./2569" → เขียนทับเลขที่จริงลงในช่องว่าง เช่น "15/2569" — เลขที่รันต่อเนื่องตามลำดับ **เริ่มนับใหม่ทุกปีงบประมาณ พ.ศ.** (ต้องเพิ่มตาราง/คอลัมน์เก็บ running counter แยกต่อปีใน DB เช่น table `request_form_numbers` หรือคอลัมน์ในนั้น เพื่อกันเลขซ้ำ/สลับกันเวลามีการ approve พร้อมกันหลาย request — ใช้ DB transaction/lock ตอน generate เลขใหม่)
2. โลโก้/หัวกระดาษ — **ไม่ต้องทำอะไร** มีอยู่แล้วใน template
3. หัวเรื่อง "แบบคำร้องขอตรวจสอบกิจกรรม" / "คณะวิทยาการจัดการ" — มีอยู่แล้วใน template ไม่ต้องเขียนซ้ำ
4. "เขียนที่..." → กรอกชื่อมหาวิทยาลัย/สถานที่ default ได้ (ตั้งเป็น constant)
5. "วันที่...เดือน...พ.ศ...." → กรอกวันที่ submittedAt ของ request (แปลงเป็น วัน/เดือนไทย/พ.ศ.)
6. "ข้าพเจ้า.......รหัสนักศึกษา......." → กรอก studentName, studentId
7. "เบอร์โทร......." → ถ้ามีข้อมูลเบอร์โทรในระบบให้กรอก ถ้าไม่มีให้เว้นว่างไว้ (อย่าใส่ "-" เพราะแบบฟอร์มต้นฉบับเว้นว่างเฉยๆ)
8. รายชื่อสาขาวิชา 10 สาขา (ลิสต์คงที่ตามในแบบฟอร์ม) — ทำเป็น checkbox/เครื่องหมาย ✓ หน้าสาขาที่ตรงกับ `users.faculty` ของนักศึกษาคนนั้น (ต้อง map ค่า faculty ในระบบให้ตรงกับชื่อสาขาในลิสต์นี้ให้ครบ ถ้า mapping ไม่ตรงกันเป๊ะ ให้ normalize string เทียบก่อน)
9. ข้อความ "ข้าพเจ้าขอตรวจสอบกิจกรรม... พร้อมแนบหลักฐาน 2 ฉบับ" — คงข้อความเดิมตามต้นฉบับ ไม่ต้องเปลี่ยน
10. เส้นคั่น
11. "ผลการพิจารณา [ ] อนุมัติเข้าร่วมกิจกรรมครบถ้วน [ ] ไม่อนุมัติ เนื่องจาก..." — ใส่เครื่องหมาย ✓ ในช่องที่ตรงกับผลจริง (approved → ติ๊กช่องแรก, ปล่อยข้อความ "เนื่องจาก" ว่าง / rejected → ติ๊กช่องหลัง แล้วกรอกเหตุผลจาก requests.rejectionReason ต่อท้าย "เนื่องจาก")
12. "ผู้ตรวจสอบกิจกรรม" + ชื่อผู้อนุมัติจริงจากระบบ (join จาก users table ผ่าน reviewedById — **ไม่ hardcode ชื่อ** "ว่าที่ร้อยตรีหญิงสุตชารัชต์ แก้วอ้น" เพราะเป็นชื่อ staff ตัวอย่างในแบบฟอร์มต้นฉบับเท่านั้น ให้ใช้ชื่อ staff คนที่กด approve จริงในระบบแทน) + วันที่ = reviewedAt
13. ตำแหน่ง "เจ้าหน้าที่ฝ่ายพัฒนานักศึกษา / คณะวิทยาการจัดการ" — ใช้เป็น constant ข้อความคงที่ (หรือถ้าระบบมี field ตำแหน่งของ staff ให้ดึงจากนั้นแทน)
14. ชื่อ-สกุลนักศึกษาผู้ยื่นคำร้อง (ซ้ำอีกรอบด้านล่างตามต้นฉบับ)

## Technical
- `PDFDocument.load(fs.readFileSync("apps/api/assets/forms/activity-request-form.pdf"))` แล้วใช้ `page.drawText(...)` เขียนทับตำแหน่งที่ระบุด้านบนทั้งหมด
- Font ไทย: embed `TH Sarabun New` ผ่าน `fontkit` (เก็บไฟล์ .ttf ไว้ที่ `apps/api/assets/fonts/`) — จำเป็นเพราะ default font ของ pdf-lib ไม่รองรับภาษาไทย
- ไฟล์ `apps/api/src/certificate.ts` เป็นจุดเดียวที่ generate — export ฟังก์ชัน `generateApprovalFormPdf(requestDetail): Promise<Uint8Array>`
- เพิ่ม running number logic: ฟังก์ชัน `getNextFormNumber(fiscalYearBE: number): Promise<number>` ที่ query+increment แบบ atomic (เช่น `UPDATE form_number_counters SET last_number = last_number + 1 WHERE year = $1 RETURNING last_number`, insert แถวใหม่ถ้ายังไม่มีของปีนั้น) เรียกใช้ตอน approve เท่านั้น (ไม่ใช่ตอน submit คำร้อง เพราะเลขควรออกตอนเอกสารสมบูรณ์/อนุมัติแล้ว)

## เงื่อนไขสำคัญ (เหมือนเดิม ต้องทำตามเป๊ะ)
- ถ้า generate PDF fail ต้อง**ไม่ทำให้ approve endpoint fail** — approve ต้องสำเร็จเสมอ (DB update ก่อนอยู่แล้ว) ถ้า PDF/email error ให้ catch แล้ว console.error เฉยๆ
- ถ้า `RESEND_API_KEY` ไม่ได้ตั้งไว้ ให้ skip การส่งอีเมลเหมือนเดิม ไม่ error
- Path ของ font/asset ต้องทำงานได้ทั้ง local dev และ Docker/Fly.io deploy — เช็คว่า Dockerfile copy asset folder เข้าไปด้วย

## ทดสอบก่อนส่งกลับ
- Generate PDF จริงจาก request ทดสอบ เทียบ layout กับต้นฉบับว่าตรงตำแหน่งดี ไม่ล้นกรอบ ไม่ทับกัน
- เช็ค checkbox ✓ ตรงสาขา + ตรงผลอนุมัติ/ไม่อนุมัติ ถูกช่อง
- ข้อความภาษาไทยไม่เพี้ยน/เป็นสี่เหลี่ยม (font embed ถูกต้อง)
